# 外部発信時の事前確認

- 外部の人またはサービスへ情報を送信・公開する操作は、実行直前にユーザーの明示的な承認を得る
- 対象には、メール、チャット、SNS、Issue、Pull Request、レビューコメント、フォーム、Webhook、ファイル共有、Git push、リリース、パッケージ公開、デプロイを含む
- 承認を求める際は、宛先、公開範囲、送信する最終内容、添付物、実行後に起きることを簡潔に提示する
- 承認前は下書き、プレビュー、ローカルでの検証までに留め、送信・公開・送信ボタンの操作は行わない
- 最終内容、宛先、公開範囲のいずれかを承認後に変更した場合は、変更後の内容で再確認する
- 最初の依頼に送信や公開が含まれていても、実行直前の確認を省略しない。沈黙や曖昧な返答を承認とみなさない
- 読み取り専用の閲覧、検索、ローカルファイルの編集、ローカルコミットは外部発信に含めない
- 実行後は、送信先、結果、取得できたURLや識別子を報告する。シークレットや不要な個人情報は報告に含めない

## GitHubリポジトリの例外

- ユーザーが所有するGitHubリポジトリ内で完結する操作は、外部発信の事前確認対象から除外する
- 所有は、リポジトリのownerが認証中のGitHubユーザーと一致する場合、またはユーザーが自身の所有リポジトリであると明示している場合に確認済みとする
- 例外には、Git push、Issue・Pull Request・レビューコメントの作成や更新、GitHub Releaseの公開を含む
- Organization所有、共同所有、管理権限のみ付与されたリポジトリは、ユーザー本人の所有が確認できない限り例外に含めない
- 所有関係を確認できない場合は、通常の外部発信ルールに従って実行直前に確認する
- リポジトリの削除、force push、公開範囲やアクセス権の変更、シークレットを含む送信など、破壊的または機密性に関わる操作にはこの例外を適用しない
- GitHubから外部サービスへのデプロイ、パッケージ公開、Webhook送信などはリポジトリ内で完結しないため、通常の外部発信ルールを適用する

## ツール権限との関係

上記は宛先・公開範囲・内容に基づく承認方針。実行時のツール権限は別に適用され、`deny`による禁止が優先される。リポジトリの所有や直前の承認を理由に、禁止された操作を実行しない。静的なコマンドパターンでは所有者や送信内容を判断できないため、GitHubの例外に該当してもツール側で確認される場合がある。設定方法と制約は[共通テンプレートの配置と検証](setup.md)を参照する。
