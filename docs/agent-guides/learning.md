# 学習内容の保存と共有

## 適用条件

訂正・再発した失敗・レビュー指摘・確定した好みから再利用できる学びが得られた場合、または今後も適用するルールの保存を明示的に依頼された場合に使う。「保存」「反映」という語だけで適用を判断しない。

## 手順

1. 訂正や再発報告を受けたら、安全に実施できる範囲で直接原因を修正し、必要な再発防止を実装・テストする。再発報告を含む質問も修正依頼として扱う。
2. 原因・解決方法・実際の結果を検証する。一回性の状況、未確認の推測、会話ログ、感情的な評価、個人情報、秘密情報は記録しない。
3. 下表で保存先を決め、既存項目を検索する。同じ内容があれば追記ではなく更新し、重複・矛盾を残さない。
4. 共通指示とプロジェクト固有の制約を混ぜない。権限・安全性・外部発信の基準を変える場合は、反映前に選択肢と影響を示して確認する。
5. 関係する索引・履歴・参照先を同期し、両ツールから正本を参照できることと変更結果を検証する。次回利用時も現在のコード・設定と照合する。
6. 保存先と検証結果を報告する。別リポジトリへの反映が必要なら変更ファイル一覧を示し、同期先・手段・権限が確認できた範囲で実施する。Gitを使わないプロジェクトはローカル検証までとする。

## 保存先の正本

| 内容 | 保存先 |
| --- | --- |
| 全プロジェクト共通の好み・ルール | 利用者が指定した共通テンプレート管理先。場所が不明なら確認し、現在のプロジェクトを全体設定とみなさない |
| このプロジェクトの制約・運用 | `docs/project-rules.md` |
| 要件・設計・安定したプロジェクト知識 | `docs/index.md`から案内する該当文書 |
| 検証済みの問題解決の行動知 | [問題解決ナレッジ](../knowledge.md)の基準・形式に従う |
| 再利用可能な複数段階の作業手順 | 共通手順文書、または既存の共有スキル。共有先と読込方法を確認する |
| 特定ツールだけに関係する設定・挙動 | そのツールの適切なスコープの設定・メモリ |

`CLAUDE.md`は`AGENTS.md`を参照する入口として保ち、共通指示を重複して書き足さない。ドキュメントの更新規則は[文書管理ガイド](../README.md)を参照する。
